# _CODEX.md — 給 Codex 的景點蒐集與自我審查規範

> **這份是給 AI 代理看的作業規範，不是給人看的欄位說明。**
> 欄位怎麼填看隔壁的 `_template.json`；**這一份講的是「查證到什麼程度才算完成」**。
>
> ⚠️ **本檔在 repo 裡的正本是 `codex_kit/_CODEX.md`。** 你手上這份是同步過去的副本，
> **改它沒有意義**（下次同步就被覆蓋）。要修規範請告訴人，由人改正本。

---

## 0. 你的任務與交件標準

蒐集常設景點，在 `交回這裡/` 底下產出 JSON 新檔。人會把它收進專案跑管線。

**判斷你有沒有做完的唯一標準：**
> 交件之後，人只需要按一下「收 Codex 交回來的檔案」看報表，
> **不需要再自己去點任何一個網址確認**。

達不到這個標準的欄位，**一律留空並在 `_note` 說明原因**。
留空是正常結果，管線會照常輸出那一筆；猜一個看起來合理的值才是失敗。

**這個專案的核心風險是「錯的看起來跟對的一模一樣」。**
地址錯了報表會顯示「成功查到座標」、營業時間抓錯了畫面上完全正常、
圖釘掛到隔壁景點在地圖上分辨不出來。所以下面每一條規則都不是形式，
每一條背後都有一次真的發生過的事故。

## 1. 三條硬規則（違反就是交件失敗）

### 1-1. 驗證網址一律用 Jina Reader，不要用 curl 或直接抓

```
https://r.jina.ai/<要驗的網址>        送 header: x-locale: ja-JP
```

- **理由**：專案的資料管線抓網頁走的就是這條。
  你用別的方式驗，驗的是「另一個世界的網頁」。
- **實例**：橫濱人形之家的 `/guide` 頁，`curl` 拿得到「開館時間 9:30〜17:00」，
  **Jina 連抓三次都沒有那一段**。當時照 curl 的結果填了 `hours_url`，
  結果管線連續 2 次抓不到，而報表上長得像「這頁沒寫營業時間」。
- **`x-locale: ja-JP` 不可省**：不送的話 Jina 那台無頭瀏覽器看起來像美國訪客，
  多語系網站會回英文版（上野動物園實測回 `9:30am - 5:00pm`）。
  ⚠️ `Accept-Language: ja` **沒有用**，那是給來源站看的，Jina 不轉送。

### 1-2. 沒有實際看過內容就不准填

**「HTTP 200」不等於「這個網址可用」。** 這個專案實際撞過四種壞法，
全部都是 200、內容豐富、看起來完全正常：

| 壞法 | 實例 |
|---|---|
| **網域已被搶註** | `www.tsurugaoka-hachimangu.jp` 變成聊天女郎招募站 |
| **設施長期停業** | 橫濱地標塔 Sky Garden 翻修到 2028 年 |
| **只有觀光協會頁、沒有官方頁** | 忍野八海、犬吠埼燈塔 |
| **DNS 有解析但連不上** | 橫濱開港資料館（疑似限日本 IP） |

**驗不了的景點就不要收**，在報告裡列出來讓人決定。

### 1-3. 不准填管線自己會算的欄位

`lat`／`lng`／`geo`／`geo_src`／`area`／`type`／`genre_ja`／`build_v`
／`hours`／`holiday`／`hours_checked`／`hours_fail`
——**一個都不要寫**，寫了會被覆蓋或造成混亂。

**日期欄位一個都不要寫，連空字串都不要。** 景點沒有結束日；
捏一個 `9999-12-31` 會跟著這筆資料跑進日後每一處讀日期的地方，而且永遠看起來合法。

## 2. 逐筆的查證流程

### 步驟 1：先確認沒收過

**開工前先讀 `現有景點.json`。** 那是同一個資料夾裡的清單，由人用工具從專案匯出，
**含已經上線的與還沒上線的（預收）兩種**——`status` 欄看得出來。

⚠️ **兩種都算收過，不要因為「網站上看不到」就再收一次。**

⚠️ **注意 `更新時間` 欄。** 那份是複製過來的快照，人若忘了同步就會過期。
**距今超過幾天就先請人重新匯出**，不要憑舊清單判斷。

- ⚠️ **`id` 撞名管線會停下來並印出是哪兩筆**，那個好處理。
  **真正危險的是「同一個景點取了不同 id」**——管線抓不到，
  結果地圖上同一個地方冒出兩顆圖釘。所以要比對**名稱與地址**，不是只比 id。
- 名稱可能不同寫法（`東京スカイツリー` vs `TOKYO SKYTREE`），地址比對比名稱可靠。

### 步驟 2：`address` — 只抄官方頁面上印的那一串

- **要含都道府縣、要到番地。**
- ⚠️ **絕對不要從地圖服務反查、不要自己補番地、不要「推測」。**
  地址是查座標唯一的依據，只寫到「東京都渋谷区」會查到**區公所**，
  而報表上會顯示「成功查到」——這是本專案最危險的一種壞法。
- 官網找不到完整地址就**留空並在 `_note` 註明**，不要用不完整的湊。
- 樓層（`45F`）、館名（`渋谷スクランブルスクエア`）可以寫進來，管線會自己往前退一段再查。
- ⚠️ **不要為了讓座標好看而動地址表記。** 富岳風穴把小字「青木ヶ原」拿掉之後
  座標判定會從 `approx` 變成 `precise`，但那個點離真正的風穴 **1.85km**。
  **寧可掛概略位置，不要拿到一個精確的錯誤。**

### 步驟 3：`url` — 官方網站

- 用 1-1 的方式打開，確認：**內容確實是這個景點的官方網站**（不是搶註站、不是觀光協會）。
- ⚠️ **永遠不要放 KKday／Klook 的網址**，那是票券那條線的事（見步驟 9），不是官網。

### 步驟 4：`hours_url` — 這一步最容易出錯，請慢慢做

**目標**：找到一頁，上面印著**這個設施本身的常規營業時間**。

先用 1-1 抓下來，然後**逐一排除下面這八種「時刻不屬於這個設施」的長相**。
它們全都通得過管線的防幻覺檢查（因為那個時刻真的印在頁面上），只有你能擋：

| 長相 | 實例 |
|---|---|
| 館內**餐廳／咖啡廳** | 三菱一号館美術館首頁只抓得到咖啡廳 11:00〜23:00 |
| **管理處／服務中心**辦公時間 | 上野恩賜公園全頁唯一的時刻 8:30〜17:30 是服務中心 |
| **電話受理**時間 | すみだ水族館首頁的 11:00〜18:00 出自 `TEL : …(11:00～18:00)` |
| **祈禱／授與所**受付時間 | 三峯神社「御祈祷受付時間 午前9時〜午後4時」——不是參拜時間 |
| **登山口**受付時間 | 日光二荒山神社「男体山 受付時間 午前6時から正午」 |
| **臨時公告**裡的時間 | 榛名神社首頁塞滿正月與大祭公告，常規時間埋在內文 |
| **園內賣店**的營業時間 | 大石公園只有賣店 9:00〜17:45（連「年中無休」也是賣店的）|
| **市／町公所的業務時間** | 新倉山淺間公園的市公式頁，全頁唯一時刻是「市役所業務時間 8:30〜17:15」|

**另外還有第九種，長相不同但一樣要擋：「只有今天的營業時間」。**
官網寫「**8月21日の**営業時間」「**本日の**営業時間」——它抓得到、當下也是對的，
**但一個月後就過期，而畫面上看起來完全正常**（八景島、陽光60展望台都是這種）。
遇到這種**不要填 `hours_url`，改標 `no_hours: true`**。

**其他注意事項：**

- ⚠️ **子頁路徑猜不到，一律從實際 DOM 的 `href` 讀。**
  多摩動物公園的營業時間頁是 `/tama/visitor-info/tickets/index.html`（**比首頁少一層 `zoo/`**，
  猜的三種全 404）；江戶東京建築園在 `/raien/holiday.php`（頁名叫「休園日／観覧料」，
  完全看不出來裡面有開園時間）。**猜出來的路徑幾乎一定 404。**
- 常見的頁名：`利用案内`／`アクセス`／`料金`／`営業時間`／`ご利用案内`／`schedule`／`guide`。
  但**不要照著試路徑**，去首頁把連結讀出來。
- ⚠️ **確認你找到的那一段真的會被節錄到。** 管線不是把整頁餵給模型，
  而是用關鍵字節錄前後各 500 字。認得的詞包括：
  `営業時間`／`開館`／`閉館`／`開園`／`閉園`／`開門`／`閉門`／`開堂`／`拝観`／
  `入館`／`入園`／`入場`／`開場`／`開室`／`閉室`／`休室`／`入室`。
  你找到的時刻附近**要有其中一個詞**，否則管線看不到它。
  （東京都廳展望室曾連續失敗 5 次，就是因為它寫「**開室**時間」而當時清單裡沒有這個詞。）
- **時刻的寫法要認得「午前9時30分」這種**，不是只有 `9:30`。
  日本行政機關與都立設施大量使用這種寫法。
- **官網憑證壞掉時 Jina 會回 422**（不是死連結）。試試看把 `https://` 改成 `http://`
  ——山中湖花之都公園就是這樣才抓得到的（它的自簽鏈不完整）。
  ⚠️ 但資料的 `url` 欄位仍然填 `https`（那是使用者會點的連結，瀏覽器多半能自動補憑證）。

**找不到合格的頁面就留空**，並在 `_note` 寫「官網查無常規營業時間頁」。留空時管線會退回用 `url`。

### 步驟 5：`no_hours` — 只在查證過「本來就沒有」時才填

標了 `true` 代表：不去抓、不呼叫模型、**不計失敗次數**。

- **合格的理由**：官網逐日公告（東京晴空塔、八景島、陽光60）／
  整站沒有一句常規時間可抄（新江之島水族館只有逐期日期表）／
  沒有門的公園、全天開放的山中神社。
- ⚠️ **不合格的理由**：「我這次沒抓到」。那是暫時的，管線本來就會保留上次的值並自己重試。
- **理由要寫進 `_note`。** 這欄一標下去，那筆就永遠不會再被自動檢查了。
- ⚠️ 標了 `no_hours` 就**不要同時填 `hours_url`**（大石公園那筆的教訓：
  填著會讓人以為還在抓，實際上完全沒有效果）。

### 步驟 6：`genre` — 八選一，一筆一類

| 值 | 也認得的寫法 |
|---|---|
| `神社寺廟` | 神社／寺廟／寺院／寺／神社寺院／神社・寺 |
| `博物館` | — |
| `美術館` | — |
| `公園庭園` | 公園／庭園／公園・庭園 |
| `水族館動物園` | 水族館／動物園／水族館・動物園 |
| `地標展望` | 地標／展望／展望台／ランドマーク・展望 |
| `自然景勝` | 自然／景勝／景勝地／滝／瀑布／渓谷／溪谷／洞窟 |
| `溫泉` | 温泉／日帰り温泉／砂湯／スパ／湯 |

- ⚠️ **`博物館美術館` 這種合併寫法會被**故意**擋下來**，管線不猜。要自己挑一個。
- **邊界判準是「人主要去做什麼」**：
  三溪園有重要文化財建築，但人是去逛庭園的 → `公園庭園`；
  根津美術館的庭園很有名，但主體是美術館 → `美術館`；
  皇居東御苑其實是江戶城跡，但大家當庭園逛 → `公園庭園`。
- **瀑布／溪谷／洞窟／岩場這種「沒有建物、人是去看地形的」→ `自然景勝`**，
  不要塞進 `公園庭園`（那會跟六義園那種人造庭園頂著同一個圖示）。
- **日歸溫泉／砂湯／溫泉主題設施 → `溫泉`**（2026-09-03 新開的第八類）。
  ⚠️ 在它出現之前這一類只能塞進 `公園庭園`，那會**跟六義園頂著同一個圖示**
  ——地圖上看起來完全正常，只是錯的。**住宿型溫泉旅館不收**（那是住宿不是景點）。

### 步驟 6b：`world_heritage` — 只有真的列名構成資產才填

**與 `genre` 完全正交**：一個景點可以同時是 `公園庭園` 和世界遺產。
是的話填 `"world_heritage": true`，**不是就整個欄位不要寫**（不要填 `false`）。
畫面上會在圖釘右上角多一顆金色星號。

⚠️ **這一欄錯了不會有任何錯誤訊息**，只會多一顆星或少一顆星，
所以判準要嚴——**只認 UNESCO 世界遺產（文化／自然）名錄上的構成資產**：

- ❌ **「日本遺産」不是。** 那是日本文化廳自己的認定，跟 UNESCO 無關，
  字面上只差一個字，**這是最容易搞錯的一個**。
- ❌ **「世界農業遺産」「世界記憶遺産」「無形文化遺産」都不是。**
  無形文化遺産是祭典、和食那種「事」，本站的景點是「地方」。
- ❌ **介紹世界遺產的設施不是**（山梨県立富士山世界遺産センター 名字裡就有
  「世界遺産」四個字，但它是一間博物館）。
- ❌ **「在世界遺產旁邊」「看得到世界遺產」不是**
  （新倉山浅間公園是拍富士山的名景，**它本身不在構成資產名單裡**；
  大石公園、山中湖花の都公園同理——湖本身是構成資產，公園不是）。
- ✅ 判準是：**這個地點的名字，出現在該項世界遺產的構成資產清單上。**
  查不到就不要填，並在 `_note` 寫「未確認是否為構成資產」。

已標的 5 筆可當範例：日光東照宮・日光二荒山神社（日光の社寺）／
富岡製糸場（富岡製糸場と絹産業遺産群）／国立西洋美術館（ル・コルビュジエの建築作品）／
北口本宮冨士浅間神社（富士山—信仰の対象と芸術の源泉）。

⚠️ **只存「是不是」，不存「屬於哪一項」。** 登錄名稱請寫進 `_note` 就好，
不要自己多開一個欄位——管線不認得的欄位會被忽略，而那看起來像有存到。

### 步驟 7：`venue` / `venue_ja` — 多數情況留空

- ⚠️ **這兩欄不只是顯示文字，Google 地圖導航是拿 `venue_ja` 組網址的。**
  填錯會把整趟行程導去別的地方，**而路線照樣畫得出來**。
- **景點名稱本身在 Google 地圖搜得到（明治神宮、東京晴空塔）→ 兩欄都留空**，
  管線會自動沿用 `title`／`title_ja`。
- **只有「景點在某棟大樓裡、名字不一樣」時才填**
  （例：teamLab Borderless 的 `venue_ja` 填 `麻布台ヒルズ ガーデンプラザB`）。
- 填之前**自己在 Google 地圖搜一次**，確認搜得到而且是對的那一個。

### 步驟 8：`id` — 發布後不可改

- `pl-` 開頭 ＋ 小寫英數與連字號，最長 40 字（`^pl-[a-z0-9-]{1,40}$`）。
- ⚠️ **分享出去的行程連結存的就是 id**，改掉等於別人手上那條連結裡的這一站
  永遠顯示「載入失敗」。名字取錯了改 `title` 就好，id 不必動。
- 取名慣例：看得懂的羅馬字（`pl-meiji-jingu`／`pl-shibuya-sky`／`pl-kadokawa-musashino`）。

### 步驟 9：票券 / `img`

- ⚠️⚠️ **`ticket_url` 這個欄位已經作廢（2026-09-02），一律不要填。**
  現行的是 `tickets` 陣列（一個景點可以有好幾件商品）。
  **填了舊欄位不會報錯、也不會有任何效果**——那顆買票鈕就是不出現，
  而清單裡明明有連結，**畫面上完全看不出來**。
- **票券一律留空，交給 `klook_match.py` 那條線處理。**
  它會去比對 Klook 的公開 sitemap，再由使用者在勾選網頁上逐件確認
  （票種、是不是這個景點的門票、要不要掛）——那是程式判不出來的事。
- `img`：**一律留空。** 照片是使用者自己去現場拍的，由另一支工具處理。
  填了但檔案不存在＝破圖，而破圖與「還沒拍」在畫面上是兩件不同的事。

## 3. 收錄範圍

**收**：
- 地標／神社寺廟／城跡
- 博物館／美術館／水族館／動物園
- 公園／庭園／自然景勝
- **有明確營業時間的邊界設施**（大型花園、牧場・動物主題園、複合型水族館）

**不收**：
- **主題樂園**（營業時間逐日公告，收了也沒有常規時間可顯示）

### 地理範圍：**全日本，26 個地區桶全部開放**（2026-09-02 起）

## 4. 輸出格式

### 檔案放哪

**一律放在 `交回這裡/` 底下。新的一批就開新檔。**

檔名建議 `<都道府縣羅馬字>-<日期>.json`，例如 `osaka-20260822.json`、
`tokyo-20260822.json`。**檔名對管線沒有任何功能意義**（它讀所有非 `_` 開頭的
`.json`），所以就算是補既有縣市的景點，也開一個新檔就好。

⚠️ **絕對不要去改專案裡 `places_src/` 的那六個檔**（你也看不到它們）。
那些是已經逐筆查證過的資料，**「合併」是人那邊的事，不是你的。**

### `交回這裡/` 裡的檔案可以改（2026-08-22 起，使用者授權）

**這個資料夾底下的 `.json`，你可以新建、修改、刪除、改名，不必每次問。**
判準是：**還在這個資料夾裡 ＝ 還沒被收走 ＝ 可以動**（收檔會把通過檢查的檔**搬走**，
所以你手上永遠只有「還沒進專案」的東西）。

- ⚠️ **被退回來的檔要就地修好，不要另開 `-02`。** 收檔時沒通過檢查的檔會**留在原地**
  並印出錯誤（id 撞名／格式不合／缺必填欄位／填了管線自己會算的欄位）。
  另開新檔的話，壞的那個還躺在那裡，下次收檔照樣被退。
- ⚠️ **`-02` 從此只代表「真的是第二批」**，不再是「我改不了原檔」的替代品。
- ⚠️ **改了什麼一定要寫進報告**（見下方第 6 項）。**尤其是刪掉或減少筆數**——
  那在資料夾裡看起來跟正常的一模一樣，沒有人會去數。

### 每一筆的樣子

```jsonc
{
  "id": "pl-nezu-museum",
  "title": "根津美術館",
  "title_ja": "根津美術館",
  "genre": "美術館",
  "address": "東京都港区南青山6-5-1",
  "url": "https://www.nezu-muse.or.jp/",
  "hours_url": "https://www.nezu-muse.or.jp/jp/guide/index.html",
  "venue": "",
  "venue_ja": "",
  "img": "",
  "_note": "hours_url 已用 Jina 實抓，含「開館時間 午前10時〜午後5時」「休館日 月曜日」。"
}
```

- **`_note` 是給人看的，管線不讀**（底線開頭的欄位一律忽略）。
  **每一筆都要有**，寫你查證到什麼、哪裡沒查到、為什麼留空。
- 沒查到的欄位**留空字串**，不要省略、不要填 `null`、不要編。

### 另外交一份報告

除了 JSON，用純文字回報這幾件事：

1. **這批共幾筆，分別落在哪個地區桶**
2. **每一筆的 `hours_url` 你實際看到的時刻是什麼**（一行一筆，讓人可以抽查）
3. **留空的欄位清單與原因**
4. **你放棄收錄的景點與原因**（官網死了、只有觀光協會頁、驗不了…）
5. **你不確定的判斷**（小類邊界、是不是同一個景點、範圍邊界）
6. **這一輪改動了 `交回這裡/` 裡的哪些既有檔**：檔名、改了什麼、**刪了幾筆、為什麼**。
   ⚠️ 沒有改任何既有檔就明講「沒有改動既有檔」——**這一項不可以省略不寫**，
   省略與「沒有改」在人眼裡是同一件事，而那正是這一項要防的。

⚠️ 第 5 項不要自己決定就算了。**不確定的東西寫出來讓人拍板，這不是失敗，是正確的交件。**

## 附錄：為什麼這份規範這麼囉嗦

因為這個專案踩過的坑，**九成的症狀都是「看起來完全正常」**：

- 地址只到區級 → 座標是區公所 → 報表顯示「成功查到」
- `hours_url` 指到館內咖啡廳 → 抓到時刻了 → 防幻覺檢查通過 → 畫面上完全正常
- 官網網域被搶註 → HTTP 200、內容豐富 → 賭場內容進到網站上
- 圖釘掛到 233 公尺外的隔壁景點 → 在地圖上跟正確的長得一模一樣

**所以「我查到了」不是完成，「我確認過我查到的是對的東西」才是。**
而當你確認不了的時候，**留空並說出來**，比填一個合理的值有價值得多。
